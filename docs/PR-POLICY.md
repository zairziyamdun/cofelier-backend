# PR Policy — бэкенд

Версия **1.0** · 15.11.2026 · изменения — в конце файла.

Правила, по которым проверяется каждый PR в `main`. Правила разработки — в
[AGENTS.md](../AGENTS.md) и [BACKEND.md](BACKEND.md), здесь — что из них
проверяем перед PR и с какой строгостью. У фронтенда свой
`docs/PR-POLICY.md`, общие пункты (G-*) в обоих одинаковые.

## Как применяется

- **Новый и изменённый код.** Правила относятся к добавленным и изменённым
  строкам. Старый код рядом чинить не обязательно; найденное — `TODO:` или
  отдельная задача.
- **Три уровня проверки:**

  | Кто | Что | Гарантия |
  | --- | --- | --- |
  | CI (GitHub Actions) | lint, typecheck, unit, build; e2e — с этапа 2 | для всех, блокирует merge |
  | `/pre-pr-review` (Claude Code) | всё из CI локально + ревью архитектуры, прав и логики | у того, кто работает в Claude Code |
  | Ревьюер PR | решение по WARNING, отклонения, контракт | человек |

- AI-ревью не блокирует merge. Блокирует CI.

## Severity и статус

| Severity | Что это | Как влияет |
| --- | --- | --- |
| **BLOCKER** | доказанная ошибка логики или регрессия; нарушение правила B в новом коде; проблема безопасности; упавшая обязательная проверка | PR не создаём, пока не исправлено или не принято отклонение |
| **WARNING** | читаемость, сложность, риск без доказательства, правило W | решает ревьюер |
| **SUGGESTION** | необязательное улучшение | не влияет |

Статусы отчёта — как у фронтенда: `BLOCKED`, `INCOMPLETE`,
`READY WITH WARNINGS`, `READY`.

## Правила

### Общие (одинаковые с фронтендом)

| ID | Правило | | Чем |
| --- | --- | --- | --- |
| G-1 | Один PR — одна задача. Перенос файлов — отдельным PR без правок логики | W | ревью |
| G-2 | Поведение и документация расходятся — док правится в том же PR | W | ревью |
| G-3 | Секреты, токены, `.env`, персональные данные — не в коде, логах, доках | B | ревью |
| G-4 | Обязательная проверка упала из-за изменений | B | CI, скилл |
| G-5 | Ветка не `main`, коммиты с префиксом, без атрибуции ИИ | W | скилл |

### Архитектура

| ID | Правило | | Чем |
| --- | --- | --- | --- |
| BE-ARCH-1 | Один модуль — одна область; чужой модуль — только через его экспортированный сервис; нет `forwardRef` и циклов | B | ревью |
| BE-ARCH-2 | Контроллер тонкий: нет `prisma.*` и бизнес-правил; Prisma — только в сервисе своего модуля | B | ревью |
| BE-ARCH-3 | Новая ручка отдаёт DTO ответа, а не строку БД (`passwordHash` и внутренние поля не утекают) | B | ревью |

### Доступ

| ID | Правило | | Чем |
| --- | --- | --- | --- |
| BE-AUTH-1 | У ручки явный доступ: `@Public()` или `@Roles(...)`, иначе — любой вошедший; роль — только из JWT | B | ревью, e2e |
| BE-AUTH-2 | Клиент видит только своё: фильтр по `userId` из токена; чужой ресурс — 404 | B | ревью, e2e |
| BE-AUTH-3 | Новая ручка — строка в матрице доступа BACKEND.md §2 и e2e на 403 для запрещённой роли | W | ревью |

### Данные и API

| ID | Правило | | Чем |
| --- | --- | --- | --- |
| BE-DTO-1 | Вход — DTO с `class-validator`; без `any` и ручного разбора `body` | B | ревью |
| BE-API-1 | Ошибки — исключения Nest с HTTP-статусом и русским `message`; нет 200 с ошибкой | W | ревью |
| BE-API-2 | Ручки и DTO описаны в Swagger; ломающее изменение контракта отмечено в PR | W | ревью |
| BE-DB-1 | Изменение схемы — только новой миграцией; старые миграции не правятся | B | ревью |
| BE-DB-2 | Связанные записи — в одной `$transaction`; деньги — не `Float` | B | ревью |
| BE-DB-3 | Сырой SQL — только параметризованный `$queryRaw` | B | ревью |
| BE-WS-1 | События WebSocket шлются после коммита транзакции, логика — в сервисе | W | ревью |

### Качество

| ID | Правило | | Чем |
| --- | --- | --- | --- |
| BE-LOG-1 | Нет `console.*`; не логируются пароли, токены, cookie | B (секреты) / W | ревью |
| BE-ENV-1 | Новая переменная — в zod-схему и `.env.example` | W | ревью |
| BE-TEST-1 | Новое правило сервиса (переход статуса, стоп-лист) — с unit-тестом | W | ревью |
| BE-SIZE-1 | Файл > 300 строк — W, > 400 — B (кроме миграций и сгенерированного) | W/B | скилл |

## Отклонения

```ts
// policy-exception: BE-ARCH-2 временный health-check без сервиса, задача #7
```

и строка в разделе «Отклонения от PR Policy» описания PR. Без причины —
WARNING.
