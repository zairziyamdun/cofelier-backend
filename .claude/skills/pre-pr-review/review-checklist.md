# Чек-лист ревью: бэкенд

Что смотреть в изменённых строках и вокруг них. ID — правила из
`docs/PR-POLICY.md`; подробности — в `AGENTS.md` и `docs/BACKEND.md`.
Бери пункты по затронутым модулям.

## Контроллер — BE-ARCH-2, BE-AUTH-1, BE-API-2

- Нет `this.prisma` и бизнес-правил: принять DTO → сервис → DTO ответа.
- Доступ явный: `@Public()` на открытой ручке, `@Roles(...)` на ручке для
  персонала. Ручка для менеджера без `@Roles` — BLOCKER: сценарий «клиент
  вызывает `PATCH /menu/items/:id` → цена изменена».
- `@CurrentUser()` вместо `req.user` руками; роль и `userId` не из тела.
- Swagger: `@ApiTags`, `@ApiOkResponse({ type })`, ответы ошибок; DTO с
  `@ApiProperty`.
- `ParseIntPipe` / `ParseUUIDPipe` на параметрах пути.

## Сервис — BE-ARCH-1, BE-AUTH-2, BE-DB-2

- Клиентские выборки фильтруются по `userId` из токена; чужой заказ — 404.
- Переход статуса заказа проверяется по допустимым переходам; недопустимый —
  `409`/`400` с понятным `message`.
- Цена позиции берётся из БД (`MenuService`), а не из тела запроса; позиция в
  стоп-листе — `409`.
- Связанные записи (заказ + позиции, смена роли + аудит) — в `$transaction`.
- Другой модуль — через его сервис, без импорта его внутренностей.
- Событие WebSocket — после успешной транзакции (BE-WS-1).

## DTO и ответ — BE-DTO-1, BE-ARCH-3

- Каждое поле входного DTO с валидатором (`@IsString`, `@IsInt`, `@Min`,
  `@IsEnum`…); вложенные — `@ValidateNested` + `@Type`.
- Ответ — DTO/маппер; в ответе нет `passwordHash`, служебных полей.
- Поля DTO и пути не сломаны для фронта без отметки в PR.

## Prisma и миграции — BE-DB-1/2/3

- Изменение `schema.prisma` сопровождается новой миграцией в
  `prisma/migrations/`; старые миграции не тронуты.
- Деньги — не `Float`.
- Новые поля в выборках — `select`, а не весь объект, если уходят наружу.
- Нет `$queryRawUnsafe` и склейки строк в SQL.
- N+1: в цикле нет запросов к БД — `include`/`in`.

## Авторизация — G-3, BE-LOG-1

- Пароль хешируется до записи; сравнение — через `argon2.verify`.
- Cookie `httpOnly`, `sameSite`, `secure` в проде; токен не в теле ответа.
- В логах нет паролей, токенов, cookie, тел запросов входа; нет `console.*`.

## Тесты — BE-TEST-1, BE-AUTH-3

- Новое правило сервиса — unit-тест (переходы статусов, стоп-лист, итог).
- Новая ручка — e2e на успех и на 403/404 для запрещённой роли.
- Строка в матрице доступа BACKEND.md §2.

## Общее — G-1..G-5, BE-ENV-1, BE-SIZE-1

- Новая переменная окружения — в схему конфига и `.env.example`.
- Поведение изменилось — `docs/BACKEND.md` / `OVERVIEW.md` обновлены (OVERVIEW
  — в обоих репозиториях).
- Файл > 300 строк — WARNING, > 400 — BLOCKER.
